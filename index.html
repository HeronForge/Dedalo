Test Specification Writer

A test specification that is also the program that writes it.

DEDALO writes end-of-line test specifications for electronic devices as one self-contained HTML file: the file is the application and the document at the same time.

Whoever receives it opens it with a double click — nothing to install, no network — reads it, navigates it, edits it and prints it to PDF.

01 / One single file

No install, no account, no server.

Save — the 💾 in the command bar — rebuilds the whole file with the current data and downloads it. The downloaded file replaces the original one and can itself be opened and edited. Nothing else is needed at either end of the exchange.

What the distributed file holds
<!--TSW:DOC--> the document data
<!--TSW:HISTORY--> the revisions, gzipped
<!--TSW:ASSETS--> the pictures, as WebP

On save only those three blocks are replaced: the file is kept in memory exactly as it was opened, and the whole interface is built at runtime.

READING MODE

A file that is the last issued revision word for word — the file as it is handed out — opens straight in reading mode, where nothing leads into the editor. Esc brings the editor back.

A NET, NOT A SAVE

Unsaved work is copied into the browser's own storage every few seconds and offered back after a crash or a window closed by mistake. The file on disk changes when you download it and not before, and the status bar says which of the two you are looking at.

KEYS

Ctrl+S saves, Ctrl+Z / Ctrl+Y undo and redo.

02 / What a specification contains

Stages, steps, points, criteria — each addressed by its code.

The steps refer to the catalogues through a code, and every reference carries both the code and the name of what it points at.

The values shown from here on are taken from the example specification — an invented product, described in full further down.

STG-xx · SET-xx
Stages and setup stages

Stages run once, in the order their prerequisites allow. Setup stages are routines with no place of their own — engage the fixture, power up, power down and discharge — run only where a step calls them, as many times as they are called. Numbered apart, listed apart, drawn in two bands of the graph.

APPLY · MEASURE · SET · GET
Tests → steps

The step carries the high-level description; the detail splits into what is put on the unit and what is read back, each with its points, resource, parameters, command and an optional wait — a number or a variable, «WAIT $PilotSettle» printing as «500 ms (PilotSettle)». A half that speaks over a bus reads SET or GET instead.

RES-xx · CMD-xx · AP-xx
Resources, interfaces, commands

An interface declares the instrument that speaks it and the points it is wired to. A command may state its nominal execution time, its decoding, and where it is defined — «Defined in REF-05» — when its specification is another document.

COMPUTED
Computed measurements

A measurement may be computed from earlier readings — (meter − reference) / reference × 100, judged against $MeterAccuracy — with its formula printed and its inputs named. It names no instrument and validation refuses an input that comes after it.

GRAPH · CONSTRAINTS
Prerequisites and exclusions

Prerequisites between stages, parallel exclusions, stimuli held on exit — checked for cycles, recursion and dangling references, and drawn in the stage graph, which prints in landscape and opens full size on a click. A stage that allows nothing alongside it says so under its own box: ⊘ not with STG-03, STG-05.

VARIABLES · GLOSSARY · NOTES
What holds the document together

Global variables — numbers with a unit, text, enumerations, booleans, ranges — read by every parameter and every limit instead of repeating a number. A glossary of the acronyms the prose uses. Notes in the margin, kept beside the specification and never part of it.

EVERY CODE HAS A CARD
— hover a code, as in the document

In the printed document the steps stay short and refer to the appendices through their codes. On screen, resting the pointer on a code previews its card; a click opens it at the side without losing your place, or opens the entity in the editor.

03 / Variants and revisions

One base document. Variants as an overlay — nothing is duplicated.

A variant is a set of operations on the base document: anything can be added, changed or removed. The matrix covers the frequent cases; for everything else you pick the variant in the top bar and edit the document — each change becomes a customisation of that variant, marked with an orange frame and undone with ↺.

EVC-22 · base document
EVC-11 · 3 phases, 16 A
two variable values, nothing else
EVC-7 S · single phase, compact
removes a stage, a test, two steps and two points
EVC-22 Pro · LTE modem
adds a command and a test

Codes do not shift under a variant: a stage keeps the code it has in the base document, and a gap in the numbering is how the document says a stage is not run here.

Whatever a variant makes different is written in electric blue wherever it is read — in the base document as in a variant.

VALIDATE

You work on a draft. Validate freezes an immutable snapshot — number, date, author, reason, status — and moves the draft to the next number. The history stays inside the file, compressed, and feeds the change record and the comparison between two versions, which produces the differences grouped by chapter.

REVISION MATRIX

The last appendix of the printed document: one column per revision that changed something, one row per thing changed, each cell saying what that revision did to it — added, changed from what to what, removed, moved — coloured by kind. A long text is counted rather than quoted.

MERGE FORWARD

Two revisions consolidate into one: the chosen revision leaves the record and what it changed belongs to the revision that follows. The model is single editor — whoever edits issues the revision and redistributes the file; opening a file with fewer issued revisions warns.

04 / From the existing PDF

A legacy specification, converted with a language model.

Old specifications usually exist as PDFs. IMPORT-GUIDE.md is written to be handed to a model together with the source document: it explains the model of a specification, gives the exact JSON format and the rules for reading a legacy text — what becomes a stimulus and what a measurement, when a repeated block is a setup stage, when a value deserves a variable, and above all not to invent what the source does not say.

The model returns one spec.json; Import data… loads it and lists whatever it could not resolve. The same guide doubles as the conceptual documentation of DEDALO, and the import also accepts a previous Export data file, so the JSON is a round-trip format.

Import report — margin notes
TO CHECK · signed «Import»
The source gives the pilot duty as a range without a tolerance — confirm against the drawing.
CONDITION · signed «Import»
Measured at 25 °C ±5 — stated in the source preamble, not in the step.
LEFT OUT · signed «Import»
§7.4 acoustic check: no instrument and no limit in the source.

What the conversion has to say beside the document does not go into the document: it comes in as notes in the margin, with their file offered from the report. Pictures cannot travel in the JSON — upload them afterwards and place the markers.

05 / Word and print

Same document, same density, on paper and in Word.

.DOCX

Heading styles, so the navigation pane works and the table of contents fills itself in with Ctrl+A, F9; tables with repeating header rows; A4 page setup; a running header with company and product and a footer with document code, revision, confidentiality and «Page X of Y».

NO LIBRARY

A .docx is a ZIP of XML parts, so it is written here directly — nothing to download, the file stays self-contained. Word cannot lay the markers over a picture, so the browser draws each figure onto a canvas first — image plus markers, and the stage graph — and embeds the resulting PNGs.

COMPACT BY DESIGN

A specification is read at the bench. Only the cover, the stages chapter and the appendices start on a new page; stage constraints are one line instead of a table; the step table keeps three columns. The same content that used to take 15 pages takes 10.

  • The project has a name: DEDALO. Its mark stands at the right end of every printed header and closes the cover with «Powered by DEDALO».

  • A measurement may be computed from earlier readings, tagged COMPUTED, with its formula printed and its inputs named.
  • The cover is signed by as many people as the process asks for — a list of signatories, each with a role, printed four to a table.
  • A glossary chapter; the editor lists the acronyms the prose uses and the glossary does not explain.
  • A revision matrix closes the printed document; the commands appendix and the stage graph print in landscape.
  • A conversion no longer writes into the document: its remarks become notes in the margin, signed «Import».
  • The data schema moves to 2 — signatory list, waits as value references. Every file written by an earlier build opens.
